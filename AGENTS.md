# Repository instructions

- Keep the upstream workload: R3 Tree-RL of BAGEL-7B-MoT (`train/online_rl.py`) with the upstream `scripts/train_rl.sh` arguments and the deviations in `docs/training.md` (4 processes, `--num_shard 4`, GenEval data and reward, the 4-prompt validation file, `--wandb_offline True`, seeds 4396 / 42): group size 16, policy group size 4, two rounds, learning rate 5e-6 constant after 10 warm-up steps, AdamW β₂ 0.95, eps 1e-8, clipping at 1.0, KL weights 0.001, ViT frozen. Do not change the model, the data or its order, the losses, the rewards, the optimizer, the sampling or the random-number consumption to gain speed. No FP8, INT8 or FP16.
- The 1.47× (1.4709×) headline is the smallest of three paired window ratios (baseline A → candidate → baseline B, independent launches on one host, 16 steps each, 10 warm-up steps, then three windows of 2 steps) on four H200-class GPUs. Do not present it as a full-training, time-to-quality or 8-GPU speedup, and do not imply that the 2× goal was reached.
- Numerical status: every recorded value of steps 0–13 (losses, rewards, advantages, rollout token and image hashes, gradient norm, learning rates, final parameter and Adam digests on all four ranks) is bitwise identical to the upstream code in deterministic mode. The rank-0 wandb values were not compared (empty hook, see `docs/judge.md`). Production-mode values, longer runs, other datasets and other GPU counts were not checked. Do not claim more.
- New changes must stay bitwise identical: the same arithmetic, reduction orders and random-number draws (including generator consumption order and shapes), and the same rollouts and rewards. CUDA-graph captures must not run extra forwards or draw extra random numbers; graphs and their pools must not outlive the text or image call (FSDP reshards and parameters change between calls).
- There are no switches. The branch `upstream` is the baseline. Keep the per-call diagnostic lines (`[static-text-graph ...]`, `[static-text-sampling-graph ...]`, `[static-flow-graph ...]`): a run without replays did not take the graph paths.
- Memory is the binding constraint on these GPUs: the baseline allocates about 131 GiB of about 140 GiB per GPU and the GenEval workers share the GPUs. Report peak allocated and reserved memory with every change that alters residency or lifetimes.
- Before trusting a timing, alternate baseline and candidate in independent launches on the same host, time only steps after the warm-up, and compare against freshly timed baselines, never against a stored number. Bitwise records do not carry over between hosts: re-record the unmodified baseline twice on a new host first.
- The bench (scripts, launch rules, baseline records) and the optimization log are a separate artifact and are not included; `docs/judge.md` describes them. Put new experiments in a new dated directory with source commit, dependency versions and hardware.
- Respect shared-host GPU locks and never stop another user's job. Use public datasets and checkpoints only. Never commit checkpoints, generated images, rewards, profiler traces, credentials, private paths, host names or per-file data listings.
